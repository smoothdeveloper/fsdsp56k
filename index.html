Why fsdsp56k

Hear the idea first. Count the cycles later. Writing a machine for the Machinedrum's DSP usually starts and ends in hand-written assembly: write it, assemble it with asm56300, pack it, send it over SysEx, and listen. The MDS standard asks you to measure each machine's worst-case cycles before you declare them. fsdsp56k shortens that loop.

01 · PROTOTYPE

A kernel is three F# functions

init, trig and render over Frac, Acc and Long: fixed-point types with the DSP's own rounding and saturation. Test it, step through it in a debugger, write a WAV in one call.

02 · AUDITION

Listen, render, stress

fsdsp56k allows you to audition and render your kernels: play them live, retrigger them, sweep their parameters, and see every call's cycles against the per-track limit.

03 · SHIP

DSP56300 code and an MDS package

The same functions compile to DSP56300 assembly, packed as an MDS package for X.20, the MDX custom firmware. Output and state are graded word for word against the prototype.

04 · OPTIMISE

An optimiser, and the listing

Passes trim reloads and spills, keep hot values in registers and pack parallel moves. See line by line which F# became which instruction, and where the cycles go.

05 · PORTABLE

The prototype runs where you work

Natively on .NET, and through Fable as JavaScript and Rust, native or WebAssembly, down to a browser AudioWorklet. We have used both, checked word for word.

06 · HAND-WRITTEN

Assembly as F#, when you want it

A DSL writes DSP56300 programs as F# values: a routine is a function you can parameterise, unroll with a loop and share between machines. It prints as Motorola syntax.

A minimal kernel

Plain F#, the DSP's arithmetic. The sine generator from Justin Mammarella's MDS examples (jmamma/MDS, sine.asm56k), ported. It runs as .NET code, and compiled it gives the same words as the original package.

Sine.fs
module samples.kernels.Sine

open dsp56k.kernel
open dsp56k.kernel.Units

type Params =
  { pitch : Frac<Hz>      // the host's pitch increment
    amp   : Frac<ratio> } // unsigned Q23

type State =
  { mutable phase   : Long    // table index . fraction
    mutable ampPrev : Frac }  // the amplitude the last block ended on

let init (_: Params) (s: State) =
  s.phase <- Long.zero
  s.ampPrev <- Frac.one

let trig (_: Params) (s: State) =
  s.phase <- Long.zero

let render (p: Params) (s: State) (out: Output) =
  let step = Acc.ofFrac (plain p.pitch) >>> 6
  let ramp = (Acc.ofFrac (plain p.amp) - Acc.ofFrac s.ampPrev) >>> 5
  let mutable gain = Acc.ofFrac s.ampPrev
  let mutable phase = Acc.ofLong s.phase
  for _ in 0 .. 31 do
    gain <- gain + ramp
    let v = Table.read Rom.sine (Acc.hi phase)
    out.Write(Acc.sat ((v * Acc.hi gain) >>> 2))
    phase <- Acc.andHi 0x7fff (phase + step)
  s.phase <- Long.ofAcc phase
  s.ampPrev <- plain p.amp

INIT TRIG RENDER

Three functions become the three entry points. render writes one 32-frame block.

Parameters and state

Records of fixed-point fields, laid out in the track's workset. [<XMemory>] puts a field in X.

Compile-time choices

A voice record read when compiling picks the code, so one engine yields several kernels, each holding only its own code.

GRADE same words

Output and state compared word for word with the .NET run and with the shipped machine, with every call's cycles against the limit.

Playground

Hear it here, in four runtimes. Pick a kernel and a runtime, then audition it live or render its phrase. The same F# runs as JavaScript and as Rust compiled to wasm; the DSP56300 runtime is The Usual Suspects' dsp56300 emulator, built for the browser, running the compiled kernel's program. Each runtime is checked block by block against the .NET reference.

Opened from disk. The .NET reference plays from its WAVs; the three live runtimes and the word-for-word checks need the page served over http. In this folder: dotnet fsi build.fsx serve, then open localhost:8056.

The command line

One tool, from source to SysEx. DSP56300 commands work on any code for the chip. The Machinedrum's live under machinedrum, or md. run, stress and audition take an MDS package, a SysEx dump, or an F# kernel as a project, a script or one file.

Write & check

asm
Assemble Motorola-syntax source to a listing and P-memory hex.
check
Assemble, then confirm every instruction against the dsp56300 oracle.
disasm
Recover a package's program as Motorola-syntax source.
import
Turn a listing or a package into F# DSL source.

Package for MDS

md info
Show a package's header, parameters, patches and checks.
md pack
Assemble a program and pack it with its MDS definition and an optional sprite.
md syx
Turn a package into a SysEx dump for a slot.
md unsyx
Split a SysEx dump back into packages.

Hear & measure

run
Render a kernel: a 24-bit WAV, per-call cycles against the limit, --profile hot spots.
auditionsketch
Play a kernel live through the sound card, retriggered with --trig-every.
audition --midi-insketch
Trigger it and turn its parameters from a MIDI controller.
stresssketch
Sweep or search the parameters for the worst INIT, TRIG and RENDER cycles.

Get started

From clone to a WAV in five lines. You need the .NET SDK and a Rust toolchain (for the native DSP56300 oracle and emulator).

terminal
$ git clone https://github.com/smoothdeveloper/fsdsp56k
$ cd fsdsp56k
$ dotnet tool restore && dotnet paket install
$ (cd native && cargo build --release)
$ dotnet run --project src/dsp56k.tool -- run tests/dsp56k.tests/Kernels/Sine.fs --wav sine.wav
